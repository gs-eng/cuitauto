# 校园网自动登录

开机后自动登录校园网，掉线了也会自动重连。只在你自己的电脑上运行，不需要管理员权限，
也不需要装任何第三方库——Python 标准库就够。

适用于**锐捷 SAM+ 新门户**（Angular 单页应用 + `/eportal/*` REST 后端），
并且已经适配了「账号密码验证完还要再选一次运营商」的门户。

---

## 三步用起来

### 第 1 步：填账号密码

把 `校园网配置.example.json` 复制一份、改名成 `校园网配置.json`，然后用记事本打开它，
把这几行改成你自己的：

```json
"userName": "在这里填你的账号",
"password": "在这里填你的密码",
"service": "在这里填你的运营商",
```

移动填 `cmcc`、电信填 `ctcc`、联通填 `unicom`（直接写「移动/电信/联通」也认）。
保存。密码只存在这个文件里，程序除了学校的门户服务器，不会把它发给任何地方。
**留空的话程序会自动挑列表里的第一个，多半会挑错，建议明确写上。**

为什么必须选：门户验证完账号密码后**会停在「选运营商」这一步**，不选就不放行网络。
这一步选错了，账号密码再对也上不了网。

> `校园网配置.json` 已经写进 `.gitignore`，填好账号密码之后 git 不会跟踪它。
> 但请记住里面存的是**明文密码**，不要把这个文件发给任何人。

### 第 2 步：先手动试一次

在本文件夹空白处按住 `Shift` 点右键，选「在此处打开 PowerShell 窗口」，然后运行：

```powershell
py "校园网自动登录.py" --check
```

看到 `在线状态：True` 就说明环境没问题。

### 第 3 步：装成开机自启

右键 `安装开机自启.ps1` → 「使用 PowerShell 运行」。

装好之后，每次登录 Windows 都会自动在后台运行；发现掉线会自动重新登录。

想取消就运行 `卸载开机自启.ps1`。

## 命令行用法

```powershell
py "校园网自动登录.py" --check      # 看看现在能不能上网
py "校园网自动登录.py" --test       # 登录一次（失败不重试）
py "校园网自动登录.py" --daemon     # 常驻后台，掉线就重连（开机自启用的就是这个）
py "校园网自动登录.py" --diagnose   # 诊断：只查看，不提交账号密码
py "校园网自动登录.py" --test --force   # 就算显示已在线，也完整走一遍登录（用来验证配置）
```

抓不到参数时的手动兜底（把浏览器地址栏那一整条 URL 交给程序）：

```powershell
py "校园网自动登录.py" --test --门户地址 "http://10.254.241.66/portal/...?sessionId=..."
```

## 守护进程的两个间隔

后台守着的那个循环，多久探测一次是可以调的：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `daemon_interval_seconds` | `300` | **在线时**多久查一次（5 分钟） |
| `daemon_offline_interval_seconds` | `20` | **掉线时**多久重试一次（20 秒） |

分开设是因为两件事的急迫程度不一样：

- 网络好好的时候没必要老去查。5 分钟一次，一天不到 300 个请求，你完全感觉不到它在跑。
- 一旦掉线就得赶紧恢复，尤其是**刚开机**那会儿——网卡可能还没拿到 IP，第一次探测就会失败。
  这时候 20 秒重试一次，最坏情况也就多等 20 秒就能上网。

改完要让程序重新读配置：重启电脑最省事，或者先运行 `卸载开机自启.ps1` 再运行 `安装开机自启.ps1`。

### 它不会重复启动

程序用「独占一个本地端口」的方式保证同一时刻只有一个守护进程在跑。
如果它发现已经有一个在跑了，会在日志里写下面这行，然后自己退出：

```
已经有一个守护进程在运行了，本次退出。
```

看到这行**不是出错**，而是保护生效了——说明后台本来就有一个在正常工作，
不需要再启动第二个。日志里如果出现同一个时刻附近有两条「守护模式启动」，
那才是异常，重启一次电脑即可。

> 这个锁必须用 Windows 上的 `SO_EXCLUSIVEADDRUSE` 才有效。
> 常见的 `SO_REUSEADDR` 在 Linux 上表示「复用 TIME_WAIT 的地址」，
> 但在 Windows 上却表示「允许别的进程抢占同一个地址」——拿它做锁等于没锁，
> 会跑出两个守护进程同时刷服务器。

## 出问题了怎么办

### 装好了但还是上不了网

先手动跑一次诊断：

```powershell
py "校园网自动登录.py" --diagnose
```

然后把 `日志\` 里最新的那个文件内容贴出来。诊断模式不会提交账号密码，可以放心贴。

### 登录失败

校园网的登录流程是：你打开浏览器访问网页 → 被交换机拦下来跳到门户 → 门户地址里带一串
**交换机生成的参数**（里面有 `sessionId`）→ 只有用这串参数才能登录。程序会自动去抓这个跳转。

抓不到那串参数就登不上。手动触发一次的办法：**在断网状态下**用浏览器随便打开一个网页，
等它跳到校园网门户页面，然后立刻运行：

```powershell
py "校园网自动登录.py" --test
```

**如果日志里出现 `getaddrinfo failed`（域名解析失败）**，说明断网时校园网连 DNS 都不给用——
域名类检测地址在那个时刻根本发不出请求，自然也就撞不上交换机的拦截。程序会自动改用两个
**纯 IP** 的检测地址（`223.5.5.5`、`1.1.1.1`），它们不需要解析域名，请求一发出去就会被
交换机拦住跳到门户，参数就在那个跳转地址里。

**最后的兜底办法**：手动把浏览器地址栏那一整条 URL 交给程序：

```powershell
py "校园网自动登录.py" --test --门户地址 "把浏览器地址栏那一整条 URL 粘到这里"
```

这种地址里的 `sessionId` 一般几分钟就失效，复制完要马上运行。

还是不行就运行诊断，把结果贴出来：

```powershell
py "校园网自动登录.py" --diagnose
```

诊断会顺带问一次门户服务器「我这台机器是谁」，正常情况下会打印出：

```
nasIp = 10.254.x.x
```

这是学校认证交换机的地址（实际值由程序自动探测，因学校而异）。
这行能出来，就说明程序能正常连上认证系统，问题只在于没抓到那串一次性参数。

### 关于风险

- 密码只存在 `校园网配置.json` 里，只发给学校的门户服务器。
- 日志里密码会被自动替换成 `***`。
- 登录失败间隔 30 秒重试，最多 3 次，不会高频刷服务器。
- 程序**不做任何绕过学校合规检测的事情**，也不抓取他人账号、不做暴力破解。

## 技术说明

门户是**锐捷 SAM+ 新门户**（Angular 单页应用 + `/eportal/*` REST 后端）。

真正用来提交账号密码的接口是：

```
POST http://10.254.241.66/eportal/workFlow/updateUserSession
{"result":"success","sessionId":"...","updateSessionData":{"userName":"...","userPwd":"...","authType":null}}
```

提交前会先调 `POST /eportal/workFlow/getCurrentNode`，看当前流程节点是不是 `authenticate`。

下面这些老接口在目标部署上**已经不可用**，程序默认不再走：

| 老接口 | 实测结果 |
| --- | --- |
| `/eportal/InterFace.do?method=login` | 404 |
| `POST /portal/portalAuthen/login` | 405（nginx） |
| `POST /portal/flowProcedure/auth` | 405（nginx） |
| `POST /api/aggregation/...` | 302 跳 `/login` |

如果哪天学校换了系统，可以在 `校园网配置.json` 里把 `enable_legacy_strategies` 改成 `true`，
程序会再去试一遍这些老接口（注意：那会把密码发到无效端点上，所以默认关闭）。

### 已经查清的事实

| 项目 | 结果 |
| --- | --- |
| 门户类型 | 锐捷 SAM+ 新门户（Angular 单页应用），公安定制版（`isLogo: 3`） |
| 前端加密 | 关闭（`crypto: false`），HTTP 请求是明文 JSON |
| 真正可用的后端命名空间 | 只有 `/eportal/*`；`/api/aggregation/*` 和 `/portal/*` 的 POST 都被拦 |
| 认证交换机 | 由程序自动探测得到（`nasIp`） |
| 交换机侧参数命名 | `wlanuserip` / `wlanusermac` / `wlanacname` 这一套经典命名 |
| 运营商列表 | 电信 `ctcc`、移动 `cmcc`、联通 `unicom`（接口要的是英文 value，不是中文名） |
| `sessionId` 从哪来 | 只有跟着 `/eportal/index.jsp` 跳一次才会出现，一次性、每次现生成，程序没法凭空造 |

### 怎么才算真的登录成功

判断标准只有一个：**网络真的通了**。程序每做完一步都会重新探测一次，
只有探测确认能上外网才会报「登录成功」。

要注意的是：**你已经在网上的时候，门户对登录这一步是直接放行的**——
账号密码对不对、运营商选得对不对，它都不检查，照样返回成功。
所以「在线时跑一遍程序，看到成功」并不能证明配置没错。
想真正验证，得在**确实上不了网**的时候跑一次：

```powershell
py "校园网自动登录.py" --test
```

日志里会依次出现这几行，才说明整条路是通的：

```
[√] 已从这一跳里拿到 sessionId。
当前节点 currentNodePath = 'authenticate'
提交账号后节点 currentNodePath = 'serviceSelection'
可选运营商：电信(ctcc)、移动(cmcc)、联通(unicom)
登录成功（服务选择方式），网络已可用。
```

### 实测记录

**真实断网环境，一次通过。** 全程如下（地址和账号已做脱敏）：

```
探测 http://223.5.5.5/ -> status=200          ← 被交换机接管，回的是门户 JS 跳转
门户跳转 URL：…/eportal/index.jsp?wlanuserip=10.x.x.x&wlanacname=<认证设备名>
  -> …/portal/portal-main?sessionId=<一次性会话>&…
[√] 已从这一跳里拿到 sessionId。
[E]  userOnline                   -> online=false
[A1] getCurrentNode               -> authenticate
[A2] updateUserSession            -> 200（userPwd 在日志里是 ***）
[A3] getCurrentNode               -> serviceSelection（userId 已变成你的账号）
[D1] serviceSelection             -> 电信(ctcc)、移动(cmcc)、联通(unicom)
[D2] serviceLogin  service=cmcc   -> {"authResult":"success"}
验证 http://223.5.5.5/ -> status=404          ← 变成真实的外部响应，确认放行
登录成功（服务选择方式），网络已可用。
```

判断「真的通了」就看最后那次探测：**同一个地址，进门时回门户内容，出门时回正常响应**，
中间没有任何猜测。

### 程序干活的顺序

1. 探测网络。在线就什么都不做。
2. 被拦住的话，跟着交换机给的跳转地址再走一跳（`/eportal/index.jsp` → `/portal/portal-main`），
   `sessionId` 就在这一跳的地址里——这是**唯一**能得到它的地方，它是一次性的，每次现生成。
3. 调 `POST /eportal/workFlow/getCurrentNode` 看当前流程节点，得到 `authenticate` 后用
   `POST /eportal/workFlow/updateUserSession` 提交账号密码。
4. 再查一次节点：如果停在 `serviceSelection`，就调 `POST /eportal/network/serviceSelection`
   取运营商列表，按配置里的 `service` 调 `POST /eportal/network/serviceLogin` 放行网络。
5. 每步之后都会重新探测一次网络，一旦通了就立刻停手，不会多发请求。
6. 实在没抓到跳转地址，就用本机 IP 和 MAC 去问 `resolveRedirectInfo` 接口，
   并把服务器说的原话原样记进日志。

### 断网时为什么要用 IP 直连探测

未认证的校园网经常连 DNS 都不放行，域名类检测地址（如 `connect.rom.miui.com`）会直接报
`getaddrinfo failed`——请求根本发不出去，也就永远撞不上交换机的拦截。

纯 IP 的检测地址不需要解析域名，是那个时刻唯一发得出去的 HTTP 请求，也就成了唯一能触发
「交换机跳门户」的机会。程序把它们排在检测列表最前面，就是为了这个。

判断「在线」的标准也随之放宽了：**只要真的收到了 HTTP 响应就算在线**——
`223.5.5.5` 回 404、`1.1.1.1` 回 301，都是真实的外部响应，说明网络是通的。

（`223.5.5.5` 排在最前面是有意为之：它是国内地址，响应稳定；
`1.1.1.1` 在国内部分网络下会超时，排在后面只作为备用，不会拖慢每次探测。）

### 日志和证据

- 每次运行写在 `日志\校园网-年月日.log`。
- 只要探测到被门户重定向，程序会把门户返回的原始内容另存成
  `日志\门户原始内容-时间-重定向.txt`，方便事后分析。
- 日志里密码一律是 `***`。
